# Доступ человека к браузеру
Используй только по прямой просьбе показать браузер, открыть ссылку управления или выполнить вход вручную. Обычная автоматизация принадлежит Browser Harness.
Создай одну локальную заявку:
```bash
curl -fsS http://127.0.0.1:8790/v1/shares -H 'Content-Type: application/json' --data '{"kind":"remote_access","target_url":"https://example.com","ttl_seconds":600}'
```
В target_url подставь запрошенный сайт; если он не задан, используй https://example.com. Ответ должен содержать share_id, public_url, otp, expires_at. Отправь пользователю и public_url, и одноразовый код otp. Отправь public_url пользователю и скажи, что ссылка действует 10 минут, а для закрытия нужно написать «готово». Браузер защищён локальным OTP на публичном домене этой VPS; центральная регистрация не используется. Не сохраняй ссылку в файлы, память или логи. Новая заявка заменяет предыдущую.
При «готово» отзови текущий share_id:
```bash
curl -fsS -X POST http://127.0.0.1:8790/v1/shares/SHARE_ID/revoke
```
Проверь revoked=true. Не выдавай прямые CDP/VNC/noVNC адреса. Центральных сервисов нет, HTTPS и lifecycle обслуживаются этой нодой.
Страница ссылки сначала показывает ввод OTP. Не расходуй одноразовый код проверочным входом перед передачей пользователю. Никогда не утверждай, что OTP отсутствует; если create не вернул otp, сообщи ошибку runtime. Не печатай URL/OTP в диагностические логи. Новая заявка делает предыдущую ссылку недействительной.
